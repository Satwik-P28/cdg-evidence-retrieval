# R163 activation-aware shared dictionary facilities

Status: all three original-code jobs passed. R162 rejects ordinary merging under per-object reconstruction budgets. Instead use independently compressed trained Zstandard dictionaries and independently decodable source frames relative to them. Actual dictionary bytes, not cache-resident fiction: cold single-object activation = compressed dictionary frame + compressed source frame; decoded = dictionary bytes + raw source. Both hard 1.5x/2.5x bounds checked for every assignment. For evidence-set reads, activate/decode each selected dictionary exactly once.

Prior art: Hoobin et al. RLZ random-access document retrieval https://arxiv.org/abs/1106.2587 ; effective dictionary construction https://people.eng.unimelb.edu.au/ammoffat/abstracts/lpmw16www.pdf ; hierarchical RLZ https://doi.org/10.4230/LIPIcs.SEA.2023.18 ; RocksDB preset dictionary compression https://rocksdb.org/blog/2021/05/31/dictionary-compression.html ; dataset versioning https://pmc.ncbi.nlm.nih.gov/articles/PMC5526644/ . Shared dictionaries, reference selection, facility location and maximum closure/min cut are established. The specific research hypothesis is exact union-aware client selection under explicit cold byte budgets, not a novel compression codec.

For fixed dictionary j and currently unassigned clients i, let s_i be actual standalone-frame saving, q_i number of training queries accessing i, U_i their query mask, T training query count. Scale objective by 100T. Benefit for selecting subset X is sum_i in X s_i*(100T+lambda*q_i) minus (lambda*compressed_dict+mu*raw_dict)*|union_i U_i| minus 100T*(compressed_dict+56). The union term is not additive per client. Solve maximum closure using source-to-client capacity benefit, infinite client-to-query implications, query-to-sink activation cost; min cut returns exact best client subset for fixed candidate (including empty choice). Constant opening cost subtracted after cut. Greedily open best positive-gain facility, never reassign. No global guarantee. Actual NetworkX pinned source min-cut implementation; test against 64 brute-force six-client problems and shared-activation counterexample. Assert exact objective changes telescope to serialized archive sizes and train workload cost. Compare singleton, global-only storage, multi-facility storage, all-client balanced, min-cut balanced/readheavy. Global/path/Louvain groups and 256/1024/4096 B dictionaries trained on offline source corpus, same train/test query roots as R162. No test workload masks in optimization. Both proof editions and Masullo formalization (not a verified proof). Validate all original bytes using parsed binary metadata and exact cold bounds; charge dictionary frame, per-dictionary digest/offset and per-source record. If gains fail or are marginal, investigate content-addressed micro-reference slices, workload hyperedge optimization or real RLZ comparators, not endless weight tuning.

## Verified results

All three R163 jobs passed on 97df1d6d (https://github.com/Satwik-P28/cdg-evidence-retrieval/actions/runs/45893453105). Readable 8,740,307 -> 8,512,626 B, compact 3,228,145 -> 3,017,265 B, Masullo 7,784,222 -> 7,678,871 B (2.60%, 6.53%, 1.35%). Global storage and facility storage identical on all three. Exact cut balanced differs from all-client only on Masullo by one assignment, 38 B more storage, 7,999 fewer heldout activated bytes. All cold bounds, objective telescoping, exact byte checks and brute-force tests passed. The optimizer has not demonstrated material advantage. Closer prior art: Delong et al. Fast Approximate Energy Minimization with Label Costs https://aosokin.github.io/files/delong12labelCosts.pdf and Chekuri/Ene Minimum Submodular-Cost Allocation https://experts.illinois.edu/en/publications/submodular-cost-allocation-problem-and-applications/ .
