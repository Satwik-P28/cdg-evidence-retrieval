# Round 74: Training-Calibrated NLI Under QA-to-Data2txt Task Shift

**Date:** 2026-11-17. **Status:** full fixed-model experiment and all five unit tests completed successfully in GitHub Actions run **44229787016**. RAGTruth source and response files and original model weights were downloaded transiently, never redistributed. This is an explicit calibration **failure/representation-interaction study**, not deployment-ready hallucination prevention.

## Question and frozen protocol

Round 72's general pretrained NLI detector falsely warned on 108 of 110 human-negative responses across QA and Summary when the rule was to warn whenever *any* sentence had entailment probability under 0.50. Could response-level confidence calibration on human-negative **QA training source groups**, rather than test labels, transfer to previously unexamined **Data2txt test source groups**? Does source representation (stable raw JSON versus a deterministic field-wise textual rendering) change the result without changing the model or threshold?

- Immutable model: **cross-encoder/nli-deberta-v3-xsmall**, full Hugging Face Git SHA **a150876415327c80daeff35ca6f68f5ed8cf5c24**, trained on SNLI/MultiNLI and **not on RAGTruth**; Apache-2.0. PyTorch CPU 2.5.1, Transformers 4.46.3, two CPU threads and fixed token caps/window configuration inherited from R72.
- Immutable input: original RAGTruth Git SHA **c103204b9ce28d6bbad859304bf30de72b8ed8fe**, with the same verified original response/source blob hashes as R69–71.
- Deterministic group selection: **24 QA train source groups**, **24 Data2txt test source groups** under a new fixed SHA salt. All source groups disjoint; **142 QA training responses** and **144 previously unused Data2txt test responses**, all marked quality good.
- 91/144 Data2txt responses have an original human annotation for unsupported content and **53/144** lack positive annotation. Positive-label prevalence is **63.2%**, much higher than QA test in R69; F1 must be interpreted against trivial always-warn controls.
- Data2txt source versions: (1) canonical sorted-key JSON representation of source structured fields, (2) deterministic field-wise text generated by stable sorted key traversal, retaining source values and keys without inference. The same generated response, human labels and model are used for both modes; they are **paired representations of one test set, not two independent samples**.
- Fixed reader: one source window chosen by claim/source content-word overlap, 150 words per window, stride 100, at most 96 windows. A response has multiple sentence-like hypotheses; max premise+hypothesis input 384 tokens; max hypothesis 128 tokens.
- Predeclared response non-entailment risk aggregations: **maximum** of 1-p(entailment), **mean** of 1-p(entailment), and **fraction** of sentences with entailment probability below 0.50. Choose training-only cutoffs to achieve no more than **10% or 20% empirical false-positive rate on original human-clean QA training responses**. Apply each frozen cutoff on Data2txt test, with no Data2txt gold label inspection for threshold choice.
- Controls: fixed R72 NLI any-sentence cutoff 0.50, original R69 word overlap, never warn; strict alternative excludes human spans marked implicit_true.

## Actual model execution cost

The run executed **3,896 real pretrained NLI premise/hypothesis pairs** across QA training plus two Data2txt source serializations. It consumed **1,090,951 tokenizer input tokens** and **550.172 seconds of shared CPU model forward wall time**. No tested hypothesis exceeded the 128-token cutoff. These are aggregate shared-batch costs and cannot be claimed as the per-policy inference latency of a deployed checker. Model weights, source window index, persistent FTS, physical SSD reads, archive decode and answer generation are not included in this specific cost boundary; R73 separately evaluates byte-exact source read costs.

Five unit tests protect train/test source-group separation, label-blind source representation, deterministic sorted field paths, fixed risk aggregation and confusion metrics.

Under both target FPR values, the train-calibrated fraction-low-entail rule hit its maximum score threshold **1.0**, flagging nothing in Data2txt. The mean-risk control can achieve a low test false-alarm rate, but only by missing almost every actual annotated positive. The maximum-risk control retains more recall in canonical JSON, but its actual held-out false-positive rate explodes to **47/53 = 88.7%** for a **9.89% empirical QA train FPR**, despite strict source-group separation. Field linearization reduces false warnings to **14/53 = 26.4%**, at the cost of missing **65/91** annotated unsupported responses.

**Important negative-control warning:** The apparent best F1 in this table, 0.77447, belongs to the trivial **warn-on-every-response** baseline. No calibrated model achieved a meaningfully satisfactory human-labeled precision/recall balance. It would be misleading to claim that model F1 0.77 demonstrated an effective verifier: it is almost entirely class prevalence.

## What changed and why no universal threshold is justified

Data-to-text sources are structured business attributes and metadata, not prose paragraphs. Their representation can shift the NLI model's entailment distribution substantially, even when underlying source values and original generated responses do not change. This variation is observed **without refitting the model or confidence thresholds**. A threshold calibrated to observed QA train error rates therefore is not guaranteed to control error on a different task domain.

The test does not prove that source JSON is inherently better or worse than verbalized fields for all NLI models. F1 and base rates differ greatly across tasks. Literal field flattening can obscure nested attribute relationships, numeric comparisons and missing-value semantics; source ordering and lexical windows affect which facts fit inside the 384-token cap. The underlying RAGTruth human annotations are source-faithfulness judgments, not an exhaustive objective truth oracle.

**Decision:** Reject broad deployment of these thresholds, reject the premise that lower train FPR implies comparable target-domain FPR, and do not promote field linearization as universally favorable. Preserve both matched negative and positive slices. A better next experiment is a task-specific trained response-conditioned semantic verifier with explicit out-of-domain evaluation and per-source risk guarantees, compared with existing LettuceDetect/MiniCheck/NLI trained controls on new data, not simply more tuning on RAGTruth.

## Further constraints

- QA training and Data2txt test source groups are disjoint but originate from the same RAGTruth overall release; this is cross-task benchmark transfer, **not** a genuinely independent external deployment dataset.
- The two Data2txt serializations use exactly the same 144 response labels, not 288 independent observations.
- Training FPR is an empirical finite-sample criterion, **not** conformal risk control or a statistical guarantee on test groups.
- Group-aware bootstrap confidence interval calculations and the alternate strict implicit_true target are saved in compact CI numerical JSON; do not interpret aggregate response counts as independent among six responses sharing a source.
- The pretrained model's SNLI/MultiNLI classification accuracy does not imply acceptable groundedness verification under source omissions or multi-claim RAG outputs.
- No new answer generation, refusal policy, hallucination suppression, source authority check, source transaction durability or physical hardware I/O benchmark was performed.
