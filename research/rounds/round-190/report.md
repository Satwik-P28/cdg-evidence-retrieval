# R190: direct cancellation-aware correction cache

R188 proves the global suffix layout is much larger than the native signed patch index on actual news revisions. R189's 28% median key reduction alone cannot close that gap. Keep the strong native signed archive; select a small cache of exact net correction vectors using corpus-only cancellation/estimated byte cost. Candidates limited to 128 common normalized tokens and up to 512 bi/trigrams comprised of these tokens. Build actual postings with native FTS5 and weighted patch mapping; gain proxy native matching rows + mapping visits - nonzero net child entries. Compare unmodified signed, frequency-ranked cache (1% cap), cancellation-ranked cache (1% and .5% caps), and native positional control. Same source/anchor archive and R188 frozen content-derived workload; 3 warm shuffled passes. Real physical complete file increment cap enforced after VACUUM. Cache stores zero vectors explicitly; lookup misses/corruption fall back to native patch rows. Digest protects accidental damage, not malicious replacement or stale cache under append. All source bytes and bounds, exact DF, all active TF maps, and native top-ten scores verified. No source decoding for ranking. No theorem from RH used. This tests whether cancellation-aware materialization is beneficial independently of the failed suffix representation. Hosted results pending.

## Decision
Stop general suffix representation optimization. Real R188 overhead too large; cache improves favorable synthetic queries but modestly changes full AP latency and does not validate cancellation-aware selection superiority. Prioritize R167/R168 signed corrections and earlier transactional evidence for ACMSE. Next research, if pursued, should address multi-revision sharing of correction operators or integration into the transaction contract, not more cache or codec tuning. No RH theorem application.
