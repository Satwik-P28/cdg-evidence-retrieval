# R120 implementation-level prior-art audit

Inspected TimIR public code at commit [90df24ba022f18280c30ffcf68fcbd0f4b7685a6](https://github.com/MoritzStaudinger/TimIR/tree/90df24ba022f18280c30ffcf68fcbd0f4b7685a6), not executed. Its README reports indexing 52,780 IR Anthology abstracts in yearly increments, using Lucene for current queries and MonetDB for historical term statistics. This is a substantially larger document count than the 2,504 revision rows in R120 (not comparable workload sizes).

- [DocumentDaoMonetDB.java, lines 164–204](https://github.com/MoritzStaudinger/TimIR/blob/90df24ba022f18280c30ffcf68fcbd0f4b7685a6/backend/src/main/java/at/ac/tuwien/lucombonet/Persistence/impl/DocumentDaoMonetDB.java#L164-L204): computes historical active-document N, historical average length, and historical DF using added/removed validity predicates. It uses log(1+ratio), approximated document length, and Lucene-compatible scoring rather than SQLite's clamped IDF and exact length formula.
- [SearchService.java, lines 123–150](https://github.com/MoritzStaudinger/TimIR/blob/90df24ba022f18280c30ffcf68fcbd0f4b7685a6/backend/src/main/java/at/ac/tuwien/lucombonet/Service/Implementation/SearchService.java#L123-L150): produces verification metadata including an MD5 over concatenated ordered result names and query/version information. Therefore query-result commitments are also directly established prior art.
- [Fast Indexing for Temporal Information Retrieval](https://openscience.ub.uni-mainz.de/items/47d63035-e20a-43af-a4a9-f4bc938d7d3c) studies HINT-based interval indexing and a time-first irHINT strategy. A simple SQLite validity join is not a novel interval-index algorithm.

CDG's prospective contribution must be evaluated as integrated compressed source reconstruction, atomic statistics and source-bound replay metadata, not the invention of validity intervals, temporal BM25, or result hashes. Different receipt fields or SHA-256 rather than MD5 do not by themselves establish novelty. For a feature-matched experiment, reproduce the native published scoring formula and tokenizer (or use an explicitly shared scoring contract), temporal validity semantics, query shape, output identity, and versioned source retrieval contract. Report storage, latency, ingestion/WAL, and source payload separately. Do not describe this code inspection as a reproduced system or performance comparison.
